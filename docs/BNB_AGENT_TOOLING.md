# BNB agent tooling review

## What was used

The official BNB Chain MCP skill was installed in this workspace's `.agents/skills/bnbchain-mcp` from the reviewed source. Codex loads the project-scoped `bnb-testnet-read` stdio configuration. The MCP harness ran the official chain, identity and contract read handlers and the official receipt service. It exposes only five reads, binds the network to `bsc-testnet`, strips inherited secrets before importing the BNB handlers and omits untrusted identity URI content from tool output. The smoke test explicitly rejected both a mainnet request and a registration request. The upstream server also has tools that can take a private key in the request body, so the workspace uses the restricted launcher. [Official skill source](https://github.com/bnb-chain/bnbchain-skills/tree/63b62af2b9f81de6afb1158de0eacc95e2e4a551/skills/bnbchain-mcp-skill) · [Official MCP tool source](https://github.com/bnb-chain/bnbchain-mcp/tree/3bd45604ee729857b0f6f114ed08357d8dd8d10e/src/evm/modules) · [Smoke evidence](../evidence/native-bnb/official-mcp.json)

The read toolkit is isolated outside the app workspace and build. A full upstream dependency install reported 14 findings including seven high severity findings. The restricted runtime drops Greenfield and unrelated packages and uses patched Zod with the MCP SDK and viem. Its production dependency audit reported zero findings. No wallet, Gemini key or deployment credential was supplied to either read check.

## Reproduce the tool check

From the game root in PowerShell, use an isolated checkout and the narrowed dependencies. These commands issue public BSC Testnet reads.

```powershell
$arenaMcp = Join-Path $env:LOCALAPPDATA 'AgentArena-BNB-Tooling/bnbchain-mcp-pinned'
git clone https://github.com/bnb-chain/bnbchain-mcp.git $arenaMcp
git -C $arenaMcp checkout --detach 3bd45604ee729857b0f6f114ed08357d8dd8d10e
Copy-Item -LiteralPath 'scripts/bnb-tooling/arena-readonly.ts','scripts/bnb-tooling/arena-smoke.mjs' -Destination $arenaMcp
'{"name":"arena-bnb-read-tools","private":true,"dependencies":{"@modelcontextprotocol/sdk":"1.32.2","viem":"2.58.7","zod":"4.6.7"}}' | Set-Content -LiteralPath "$arenaMcp/package.json" -Encoding utf8
npm install --ignore-scripts --omit=dev --prefix $arenaMcp
node "$arenaMcp/arena-smoke.mjs"
npm audit --omit=dev --prefix $arenaMcp
```

The workstation Codex entry launches `node` with the project's installed `tsx/dist/cli.mjs`, then `--tsconfig` and the isolated checkout's `tsconfig.json` and `arena-readonly.ts`. The working directory is the isolated checkout. `codex mcp get bnb-testnet-read --json` verified the project configuration and explicit `enabled_tools` allowlist. The protocol smoke uses that launcher directly over stdio. The app uses its own viem reader at runtime.
