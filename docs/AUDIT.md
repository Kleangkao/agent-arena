# Prototype audit and test inventory

- The master specification file is byte-for-byte identical to the provided original (SHA-256 checked), and headings 00–50 exist. `IMPLEMENTATION_PLAN.md` was expanded from its previous one-paragraph summary.
- Rules are a one-dimensional 0–6 lane, not the specified map node/layer/height/connection model. Both sides start with 100 health and 3 ammunition. A step resolves simultaneous wait, advance, attack, or reload; at 10 steps or defeat it ends. Bounds and state validation are not comprehensively enforced for arbitrary injected state. No utility actions exist.
- The Phaser view draws placeholder shapes from current state. It is not a stored event-stream replay, and character animation is a tween plus attack flash. The player avatar is a diamond. There is no depth sorting, animation state set or final art.
- Prior six tests checked repeatability/termination for fixed bots, illegal attack, simultaneous defeat/draw, immutable input, wait-only termination and attack range. The previous Solidity parity test checked selected action pairs through four depths, truncated to 12 states per depth; it did not prove complete-match parity, security, settlement, or gas.
- New replay tests check malformed/oversized transcripts, terminal behavior, equal starting resources, 200 seeded legal matches with bounds and repeatability, and one mirrored sequence. New Solidity tests compare 80 seeded complete matches and reject representative malformed transcripts. This is sampling, not exhaustive proof. The local all-wait 10-step read-only simulation gas estimate is 51,448; this is not a settlement gas measurement.
- UI inspection: an actual match completed and rematch was available. Teams can be distinguished by color but characters are small block shapes; map has sparse geometry and no convincing walls/arches or mature isometric depth; pixel scale and animations need refinement; the HUD is legible but the agent page uses a placeholder diamond. Screenshots were inspected in the browser but not saved as files; no recording was captured. Responsive/mobile and independent user tests remain incomplete.
- API binds to loopback and rejects unapproved browser origins; it still accepts client-controlled state and legal choices. Loopback restriction is not user authentication, does not stop other local processes, and is not suitable for staging or public exposure. No server-owned match, guest isolation, rate limiting or durable memory exists.
- The complete npm audit initially reported 18 findings, inherited from a direct unused Hardhat toolbox, its transitive dependencies, Hardhat/Zod and solc/tmp. Removing the unused toolbox and overriding transitive `tmp` to 0.2.7 reduced the report to 3 high findings. Remaining findings are the same Zod collection-allocation DoS advisory propagated through dev-only direct Hardhat and transitive hardhat-zod-utils/zod 3.25.76. Production-only audit reports zero. Hardhat expects Zod 3, so forcing Zod 4 or downgrading Hardhat without a compatibility review is inappropriate. The vulnerable validation is potentially reachable if untrusted oversized input reaches Hardhat tooling; current tests use local trusted fixtures. No claim of complete non-reachability is made. See https://github.com/advisories/GHSA-mrhx-c7xc-m3w5.
- API secrets remain on the server/CLI; local test reads a user-specified file via `GEMINI_KEY_FILE` and does not copy its contents into the repository. Never commit credentials. AI reports contain coaching and match data and are gitignored.

Current local AI evidence: one genuine Gemini-versus-Gemini match completed and replayed consistently. A side-swapped comparison was interrupted after three turns by inference timeout; the sample is insufficient to establish a reliable coaching effect. Provider availability and latency are product risks.
